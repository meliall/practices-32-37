# Практическая работа 35 — роли и доступ

**Вариант 21:** страница демо-регистрации сразу создаёт пользователя с ролью `user`.

Установка: `npm install`. Запуск: `npm run dev`. Проверка: `npm test`, сборка: `npm run build`.

Учётные записи из теории:
- `admin` / `admin123` — администратор.
- `user` / `user123` — обычный пользователь.

Маршруты: `/login`, `/register`, `/profile` (user и admin), `/admin` (только admin).
Guard перед каждым переходом проверяет токен и роль. Гость попадает на вход с параметром
`redirect`; обычный пользователь при попытке открыть `/admin` возвращается в профиль.
Кнопка перехода в панель администратора показывается только админу.

Store хранит ключи `auth_token`, `auth_role`, `auth_user`. При выходе они удаляются.
Пароли в localStorage не сохраняются. Регистрация демонстрационная: постоянная учётная
запись на сервере не создаётся; после выхода доступны исходные демо-логины.

Перед запросом `/posts/1` у JSONPlaceholder проверяется токен, добавляется `Authorization: Bearer`.
Ответ 401 завершает сессию, ошибки сети и другие HTTP-ошибки показываются на странице.
Права здесь имитируются на клиенте: открытый тестовый API настоящую роль не проверяет.
8 тестов проверяют вход, хранение сессии, выход, регистрацию и ограничения маршрутов.
